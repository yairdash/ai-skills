# GitHub בלי להסתבך

**Repository** הוא תיקיית פרויקט עם היסטוריית שינויים. **Git** הוא הכלי שמנהל את ההיסטוריה; **GitHub** מאחסן עותק מקוון שלה.

| מושג | מה עושים איתו |
|---|---|
| Clone | מורידים עותק עבודה של המאגר |
| Commit | שומרים קבוצת שינויים עם תיאור |
| Push | מעלים את הגרסאות ששמרנו ל־GitHub |
| Pull | מביאים שינויים מהמאגר המקוון לעותק המקומי |
| Branch | עובדים על גרסה נפרדת לפני שילובה |
| Pull Request | מציגים שינוי לבדיקה לפני שילוב |
| Fork | יוצרים מאגר משלך על בסיס מאגר של מישהו אחר |

קישור למאגר אחר בקטלוג אינו Fork או Clone. הקבצים ממשיכים להיות אצל בעל המקור. העתקת סקיל למאגר שלך נותנת לך שליטה בגרסה, אך דורשת טיפול בעדכונים וברישיון.

## העבודה היומיומית שלך

אפשר לנהל את הספרייה באמצעות בקשות ל־AI. אם תרצה לעבוד בעצמך, [GitHub Desktop](https://docs.github.com/en/desktop/overview/creating-your-first-repository-using-github-desktop) מציע ממשק גרפי לצפייה בשינויים, Commit, Push ו־Pull. שתי ספריות הפרסום הן שני מאגרים נפרדים; מוסיפים כל אחת ל־Desktop בנפרד לאחר חיבורן ל־GitHub.

לעריכת טקסט בודדת אפשר לפתוח את הקובץ באתר GitHub ולהשתמש בכפתור העריכה. שינוי catalog.json מחייב גם יצירת CATALOG.md מחדש ובדיקתו; עדיף לעשות זאת באמצעות הסוכן או בעותק המקומי.
