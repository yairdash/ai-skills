# Foundation prompts and selection

## Prompt contents

Write a prompt for the image's exact job. A useful order is:

1. **Purpose:** identity reference, wardrobe reference, location master, prop study or style exploration.
2. **Design:** concrete observable features, proportions, materials, palette relationships and distinguishing marks.
3. **Inheritance:** which actual supplied references control which attributes; which incidental attributes must not carry over.
4. **Presentation:** framing/views, visibility, background and lighting that reveal the required evidence.
5. **Constraints:** only meaningful exclusions or boundaries that prevent design ambiguity.

Keep production notes and acceptance checks outside the generation prompt. Mention existing images by real filename or a clear proposed binding map; until attachments are bound, do not claim that an `Image 1` token exists. Adapt syntax only after choosing and checking the target tool. Exact logo or typography reproduction may require separate artwork and compositing rather than a promised text-to-image result.

For characters, avoid dramatic action that hides costume or changes the silhouette. For locations, show design and layout rather than prescribing the eventual story camera. For props, reveal working surfaces and contact points instead of surrounding them with irrelevant cinematic atmosphere. Ask for clean separate design evidence when a dense collage would obstruct later use.

## Compare candidates by role

First eliminate candidates with a material failure, then compare the remaining ones. Do not let overall beauty outweigh an identity or geometry defect.

| Check | Evidence to inspect |
|---|---|
| Identity/design | Required distinguishing details, silhouette, proportions and readable features |
| Completeness | Important parts visible; relevant surfaces and mechanisms understandable |
| Consistency | Matches the intended state, approved palette/materials and existing canonical references |
| Usability | Crop, background, perspective and light support the assigned role |
| Leakage | Unwanted people, outfits, objects, labels, panels or scene details likely to contaminate reuse |
| Technical fitness | Actual file can be accessed and meets the chosen tool's checked input contract |

If only written descriptions are available, provide these as future review criteria, not completed checks. If an image is unavailable or too unclear to judge, mark it unverified. A provisional candidate may help exploration without becoming an approved reference.

Recommend a candidate with a short role-based reason and known limitations. The user or designated team authority approves it unless approval has already been explicitly delegated. Preserve rejected candidates outside the active reference pack; do not attach all variants to future prompts.

## Updates and handoff

Record approval against a version and actual file, not a floating filename. When a canonical identity, costume, prop mechanism or layout changes, mark dependent variants as needing review. Unaffected entities remain approved. Keep the previous approved file available for rollback.

The next stage receives the bible version, relevant approved IDs/files, their roles and invariants, allowed changes and unresolved gaps. Do not pass exploration images as approved identity anchors. Generating an opening frame is a separate request; that frame combines the approved designs with a specific story moment and camera decision.
