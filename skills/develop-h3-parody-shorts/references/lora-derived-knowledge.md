# LoRA-Derived Knowledge

Use this layer before character-bible writing when a property is on the parody shortlist. Its purpose is vocabulary discovery, not adapter use.

1. If the current project provides `research/lora-observations.jsonl` or `research/lora-prompt-ingredients.md`, read them. Otherwise collect attributed observations only when needed; do not assume those files exist.
2. Prefer project-demonstrated and official H3 evidence. Treat direct local-H3 adapter claims as local-only unless independently tested; treat peer-model adapters as hypotheses.
3. Retain only short, attributable details that clarify a visible shot: silhouette, wardrobe era, set anchor, movement, performance, framing, or a documented failure risk.
4. Convert a useful trigger into plain language. Do not automatically insert it into an H3/FAL prompt.
5. Reject generic terms, copied dialogue, recreated scenes, actor-audio implications, and unresolvable franchise-version ambiguity.

For every proposed anchor, record one provenance label: `project-demonstrated`, `official`, `community-reported`, `LoRA-derived`, or `inferred`. If an adapter and H3 evidence conflict, H3 evidence controls the production decision.
